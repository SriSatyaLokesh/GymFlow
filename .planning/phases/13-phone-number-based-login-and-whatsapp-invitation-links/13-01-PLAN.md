# Phase 13 Plan 01: Phone Number Based Login & WhatsApp Invitation Links

## Objective

Replace standard OTP-based SMS verification with a secure, zero-cost password-based phone authentication mechanism. We will leverage Firebase's existing `Email/Password` provider under the hood by mapping a normalized 10-digit phone number to a synthetic email address format (`[normalized_phone]@gymflow.app`). Gym owners can add members, auto-generate pre-filled WhatsApp invitation links containing registration tokens (`invite=[MemberId]&phone=[PhoneNumber]&code=[GymCode]`), and members will set their own passwords to activate their accounts.

---

## Proposed Changes & Tasks

### Task 1: Phone Normalization Utility
- Add `normalizePhone10(value)` helper in `modules/utils.js` that strips all non-digit characters and extracts only the last 10 digits.
- Update `lib/firebase-init.js` to normalize the `mobile` field using `normalizePhone10` before checking duplicates or performing updates.

### Task 2: Login UI & Dynamic Auth Mapping
- Update `modules/auth.js` login form:
  - Change the "Email" field label to "Email or Phone Number".
  - Change the input `type` from `email` to `text` to prevent native browser validation errors when entering digits.
  - In the sign-in form submit handler, detect if the input is a phone number (i.e. all non-digit characters stripped matches a 10-digit number and input lacks `@`).
  - For phone number inputs, normalize the number using `normalizePhone10`, append `@gymflow.app`, and pass it to the existing `context.services.auth.login(syntheticEmail, password)` function.
- Update `lib/firebase-init.js` `login` function in both Firebase and Demo mode:
  - Normalize incoming email parameters: if they represent a raw phone number (all digits), automatically append `@gymflow.app` before checking credentials or calling Firebase.

### Task 3: Member Invitation & Pre-filled Params
- Update `modules/members.js`:
  - When saving a new member, if `email` is empty and `mobile` is entered, automatically generate and save the synthetic email address (`[normalized_phone]@gymflow.app`) to the member document.
  - When rendering the Member Directory rows for pending members (where `!member.uid`), add a "Send Invite" action button (using the `chat` or `share` icon).
  - When clicked, compute the WhatsApp URL with pre-filled, URL-encoded invitation message text:
    ```text
    Hello [Member Name]! Welcome to [Gym Name]. 

    To register and access your workouts, schedules, and consistency points, please open the GymFlow App and set your password:
    [AppURL]/#register?invite=[MemberId]&phone=[PhoneNumber]&code=[GymCode]
    ```
- The `AppURL` is resolved dynamically via `window.location.origin + window.location.pathname`.

### Task 4: Onboarding Registration Page
- Update `modules/auth.js` initialization and `renderAuth`:
  - Check if `location.hash` contains `register` and has query parameters.
  - If query parameters `invite`, `phone`, and `code` are present:
    - Activate the "Register" tab and select the "Join as member" sub-registration form.
    - Pre-fill the "Gym code" input with the query `code` value and disable it.
    - Change the "Email" input field of `member-register-form` to display as "Phone Number", pre-fill it with `phone`, and disable it.
    - During submission, the app will pass the pre-filled phone number appended with `@gymflow.app` as the `email` to `context.services.auth.registerMember`.
- The existing `registerMember` linking logic will automatically find the matching pending member doc in Firestore (since the email matches the pending member's synthetic email) and link the user account seamlessly.
